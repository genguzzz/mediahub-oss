# 入库流水线（任务）

每个资源（种子 hash）一个任务，影视 / AV / 里番 共用一套。主人在 App「任务」页看进度，tasks 工具能读。

## 六步
1. **搜索选片**：谁挑的（订阅 / 自动 / 手动 / 换资源 / RSS / 目录）、策略评分和理由。
2. **提交**：磁力提交 115 离线，存到作品的标准目录。
3. **115 离线 / NAS 缓冲**：看 115 进度。0% 超过 30 分钟算「卡住」并提醒（App 里可「改用 NAS 缓冲」或「换一个资源」）；6 小时自动改用 NAS 缓冲（qBittorrent 下完再上传 115）。死种 / 太大 → 拉黑。
4. **生成 strm**：在媒体库目录写指向 115 文件的 strm（影视按 TMDb 季集命名；里番按 Bangumi；AV 进 MDC 刮削收件箱）。
5. **刮削**：通知 Emby 刷新/扫描，Emby 推送确认后进下一步；AV 等 MDC 刮削完。
6. **完成**：Emby 确认入库。3 小时还没确认 → 列进健康检查。

## 状态（status）
- downloading 下载中 · uploaded 已下完待生成 strm · scraping 刮削中 · done 完成
- 失败类：dead 死种 · too-big 太大 · no-video 没认出可入库的视频 · strm-failed 生成 strm 连续失败 · needs-id 待识别（没对上作品/Bangumi）· superseded 库里已有其他版本 · cancelled 已取消
- 资源本身不能用（死种/太大/没视频）会**拉黑并回滚订阅**里的已下载集，MP 会自动换下一个候选。

## 主人能做的（在任务详情里）
重试（重新生成 strm / 重新提交 115 离线 / 改用 NAS 缓冲）、换一个资源、改为另一部（认错作品时）、取消。你能用 retry_task 重试；换资源、取消、删除只能主人在 App 里做。
