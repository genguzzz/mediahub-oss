# AI 助手

A chat assistant in the app (floating orb above the tab bar: tap = chat sheet, hold = talk; slide up cancels, slide left starts a new chat). It recommends from the owner's taste, finds works from vague descriptions, explains plots, reads the library and ingest pipeline, and searches / ingests / subscribes when asked.

## Server (`server/src/ai/`)

- `settings.ts` — API key, endpoint (Anthropic-compatible base URL), model, thinking effort (`low` / `medium` / `high`, default `medium`; sent as `output_config.effort` with adaptive thinking); the chat header's model chip opens a menu (`components/ai/ModelMenu.tsx`) where this phone picks model, effort and web search per turn — sent with each question as `model` / `effort` / `webSearch`, unset ones follow these defaults, web search. Environment (`AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `AI_EFFORT`, `AI_WEB_SEARCH`) is the default; values set from the app (`PUT /v1/ai/settings`) or admin (`PUT /admin/ai/settings`) are stored in `DATA_DIR/ai/settings.json` (mode 600) and win. `""` clears a stored value. The key is never returned, only "set, N chars, last 4".
- `client.ts` — the Anthropic SDK with undici's fetch on an `AI_PROXY` dispatcher. No proxy → the chat answers "not configured"; there is no direct path.
- `chat.ts` — a turn runs detached from the request (10 min cap, 2 at a time). Events are buffered and fanned out as SSE; `/stream` replays the running turn from its start; `/stop` aborts; a question left without an answer (restart) shows as `interrupted` and `retry` re-asks it. Chats: `DATA_DIR/ai/chats/<id>.json` (app messages with steps + the model's own history, last ~40 messages). Memory: `memory.ts`, `DATA_DIR/ai/memory.json` (see Memory below).
- `tools.ts` — each tool calls this server's own `/v1` routes in-process (`app.inject` with the app token), so validation, caching and library lookups are shared; outputs are slimmed (posters as file names, overviews cut). Tiers:
  - read: `search_media` (one title, candidates), `lookup_titles` (batch: ≤ 20 titles → TMDb + inLibrary, `POST /v1/media/lookup`), `douban_related` (豆瓣 喜欢这部的也喜欢, resolved to TMDb, `GET /v1/douban/related`), `media_detail`, `community_reviews` (Douban star distribution, watched / wish counts, hot short comments with each writer's stars, top reviews — `server/src/reviews.ts`; TMDb user reviews in English and Chinese — plugin `/hub/tmdb/reviews`; both in `GET /v1/reviews`), `related_media`, `discover`, `tmdb_discover`, `person_works`, `library_search`, `library_latest`, `watch_history` (`/v1/emby/played`: recent = played + resume by last played, with dates — Emby only sends them for `Fields=UserDataLastPlayedDate,UserDataPlayCount` — adult items dropped before the limit), `tasks`, `subscriptions`, `health`, `platform_status` (live libraries / counts / space / tasks / problems), `read_knowledge`, `find_resources` (smart, or by source with `sources` + up to 4 `keywords`), `list_sources`, `browse_indexers` (Prowlarr catalog, public / addable by default), `video_search` (Bilibili + YouTube by topic, `GET /v1/ugc/search`), `creator_videos` (an UP 主 / channel: account, latest uploads, Bilibili live state — `GET /v1/ugc/creators`, `/v1/ugc/uploads`), `find_creators`, `live_search` (Bilibili live rooms, `GET /v1/ugc/live?q=` / `?uids=`) — all in `server/src/ugc.ts`; `catalog_list` / `catalog_item` only when 隐藏内容 is on (the app sends `adult`).
  - write (ordinary user actions, only when asked): `cast_to_tv` (a library movie or episode to a TV by DLNA: the server sends a `cast` event with a request id, the app — on the TV's network — casts to the named / last-used / first-found TV and posts the outcome to `POST /v1/ai/cast/:rid`, which the tool waits ≤ 45 s for; `app/src/lib/assistantCast.ts`), `ingest_resource` (by the short ref `find_resources` gave — the model never handles magnets), `auto_ingest` (batch: one `/v1/ingest/auto` job for ≤ 20 works), `subscribe`, `retry_task`, `refresh_library_item`, `manage_indexer` (add a public Prowlarr indexer by definition, enable / disable one; never delete).
  - memory: `memory_save`, `memory_search`, `memory_forget`; past conversations: `list_chats` (search titles and Q&A, snippets) and `read_chat` (one chat's text, poster cards as their works in order). The last six chat titles are in every system prompt.
  - nothing deletes, cancels, stops services, changes other configuration or reads credentials; only the listed routes are reachable.
  - plus the API's `web_search` and `web_fetch` server tools (fetch reads a found page or a link the owner gives; ≤ 5 per turn, ≤ 8k tokens each) unless web search is turned off.
- `prompt.ts` — system prompt (English, answers in Chinese). It tells the model to batch (lookup_titles, auto_ingest, parallel calls; 3–5 rounds per recommendation) and to treat titles as possibly mis-heard: questions sent from speech arrive marked `[语音输入…]` (app sends `voice: true`), and an odd or unknown title is tried as homophones against recent plays, the library and web search before asking. Answers may contain ```` ```video [{site,id,title,author,duration,views,cover}] ```` blocks (landscape cards; Bilibili live rooms as `{live:true, id:<roomId>, online, area}` with a 直播中 badge, opening `bilibili://live/<id>`; tap opens the Bilibili / YouTube app via its URL scheme, else the page in the in-app browser) and ```` ```media [{type,tmdbid,title,year,poster,inLibrary,why}] ```` blocks — the app renders each card as soon as its object has streamed (shimmer placeholders for the rest), with 已入库 badges, 入库 per card and 全部入库 (one batch `/v1/ingest/auto`, after a confirm) and links like `[绝命毒师](/media/tv/1396)`, `/person/<id>`, `/task/<hash>`, `/emby/<id>`, `/tasks`, `/settings`.

SSE events: `chat {chatId}`, `text_start`, `text {delta}`, `think_start`, `think {delta}`, `think_end {ms}`, `tool {id,name,label}`, `tool_input {id,input,label}`, `tool_done {id,ok,output}`, `memory {text,replaces}`, `done {text,latencyMs}`, `error {error}`, `idle`; `: ping` every 15 s.

## Memory

Two layers (after Letta/MemGPT core vs archival, mem0's update-not-duplicate, Claude's memory tool): `profile` (≤ 12 stable taste / rules, always in the prompt) and archival `fact` / `watching` / `event` / `plan` (searched). Each turn, the archival entries most relevant to the question (+ chat title) are recalled into `<recalled>`; scoring is character-bigram overlap (no tokenizer, fine for Chinese) + tag hits + recency + use, in memory. `memory_save` updates a near-duplicate of the same kind (similarity ≥ 0.72) or `replaces=id` instead of adding; writes are serialized. Cap 400 entries (least recalled archival ones drop first). The app's 偏好与记忆 pane is `/v1/ai/notes` over the same store (owner entries are `profile`). The old `notes.json` migrates to `profile` on first load.

The system prompt is two blocks: a stable one (cached; changes only with 隐藏内容) and a per-turn one (time, profile, recalled, recent chats, screen).

## Knowledge (progressive disclosure)

`server/src/ai/knowledge/<topic>.md` — generic, owner-readable notes on how the stack works (platform, ingest, subscriptions, emby, selection, app, troubleshooting, adult). The system prompt carries only the index (`knowledge.ts` TOPICS, one line each; `adult` only with 隐藏内容 on); `read_knowledge` loads a topic when a question needs it. Nothing deployment-specific goes in these files — live values come from `platform_status`. Update the topic when the behaviour it describes changes.

## App

`src/lib/ai.ts` (state + connection: expo/fetch streaming, 40 s stale watchdog, backoff reconnect, resume on foreground / network), `src/lib/voice.ts` (hold / tap to talk on iOS speech recognition), `src/components/ai/*` (orb, step cards, Markdown, media blocks, history and preference panes), `src/app/ai.tsx` (the sheet), `src/components/AiSettings.tsx` (Settings → AI 助手). The orb passes the page it was opened from (work / person / task / Emby item / adult item) as context.
