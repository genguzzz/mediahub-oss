# AI 助手

A chat assistant in the app (floating orb above the tab bar: tap = chat sheet, hold = talk; slide up cancels, slide left starts a new chat). It recommends from the owner's taste, finds works from vague descriptions, explains plots, reads the library and ingest pipeline, and searches / ingests / subscribes when asked.

## Server (`server/src/ai/`)

- `settings.ts` — API key, endpoint (Anthropic-compatible base URL), model, thinking effort (`low` / `medium` / `high`, default `medium`; sent as `output_config.effort` with adaptive thinking); effort `off` turns thinking off. The chat header's model chip opens a menu (`components/ai/ModelMenu.tsx`) built from `GET /v1/ai/options` (models, levels — 默认 first —, web search default; the same shape as OKX Helper's) where this phone picks model, effort and web search per turn — sent with each question as `model` / `effort` / `webSearch`, unset ones follow these defaults (set in the environment or `PUT /admin/ai/settings`; the app's Settings only holds key and endpoint), web search. Environment (`AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `AI_EFFORT`, `AI_WEB_SEARCH`) is the default; values set from the app (`PUT /v1/ai/settings`) or admin (`PUT /admin/ai/settings`) are stored in `DATA_DIR/ai/settings.json` (mode 600) and win. `""` clears a stored value. The key is never returned, only "set, N chars, last 4".
- `client.ts` — the Claude Agent SDK (the Claude Code harness, as in OKX Helper): one CLI process per turn (`@anthropic-ai/claude-agent-sdk`, its platform binary from the lockfile), environment replaced entirely — the key (`ANTHROPIC_API_KEY`, or `CLAUDE_CODE_OAUTH_TOKEN` for `sk-ant-oat…`), optional base URL, `HTTPS_PROXY` = `AI_PROXY` (must be http(s); no proxy → the chat answers "not configured", there is no direct path), state in `DATA_DIR/ai/claude` (session transcripts). Built-in tools: only WebSearch / WebFetch (when web search is on); ours are an in-process MCP server `mediahub` (`tools.ts` `mcpServer`, names `mcp__mediahub__<tool>`); `permissionMode: dontAsk`, no settings files.
- `chat.ts` — a turn runs detached from the request (10 min cap, 2 at a time) as one SDK `query`: the conversation is the SDK session (`Chat.sessionId`, stored as soon as the first message names it and resumed every turn), so a stopped or failed turn keeps its context, and the harness compacts long conversations itself. The stable system prompt is the SDK's custom system prompt (not snapshotted); time, memory, recent chats and the screen go in front of the question as `<turn_context>`; chats from before the SDK get their last exchanges once as `<earlier_in_this_chat>`. Stream events (`includePartialMessages`) map to the app's events; tool inputs come from assistant messages, results from user messages, usage and cost (`total_cost_usd`) from the result. Events are buffered and fanned out as SSE; `/stream` replays the running turn from its start; `/stop` aborts; a question left without an answer (restart) shows as `interrupted` and `retry` re-asks it. Chats: `DATA_DIR/ai/chats/<id>.json`. Memory: `memory.ts`, `DATA_DIR/ai/memory.json` (see Memory below).
- `tools.ts` — each tool calls this server's own `/v1` routes in-process (`app.inject` with the app token), so validation, caching and library lookups are shared; outputs are slimmed (posters as file names, overviews cut). Tiers:
  - read: `search_media` (one title, candidates), `lookup_titles` (batch: ≤ 20 titles → TMDb + inLibrary, `POST /v1/media/lookup`), `douban_related` (豆瓣 喜欢这部的也喜欢, resolved to TMDb, `GET /v1/douban/related`), `media_detail`, `community_reviews` (Douban star distribution, watched / wish counts, hot short comments with each writer's stars, top reviews — `server/src/reviews.ts`; TMDb user reviews in English and Chinese — plugin `/hub/tmdb/reviews`; both in `GET /v1/reviews`), `related_media`, `discover`, `tmdb_discover`, `person_works`, `library_search`, `library_latest`, `watch_history` (`/v1/emby/played`: recent = played + resume by last played, with dates — Emby only sends them for `Fields=UserDataLastPlayedDate,UserDataPlayCount` — adult items dropped before the limit), `tasks`, `subscriptions`, `health`, `platform_status` (live libraries / counts / space / tasks / problems), `read_knowledge`, `find_resources` (smart, or by source with `sources` + up to 4 `keywords`), `list_sources`, `browse_indexers` (Prowlarr catalog, public / addable by default), `video_search` (Bilibili + YouTube by topic, `GET /v1/ugc/search`), `creator_videos` (an UP 主 / channel: account, latest uploads, Bilibili live state — `GET /v1/ugc/creators`, `/v1/ugc/uploads`), `find_creators`, `live_search` (live now on Bilibili and YouTube — `GET /v1/ugc/live?q=&site=`, YouTube by the search's Live filter; `?uids=` for UP 主 live state), `video_content` (a YouTube video's top comments `GET /v1/ugc/comments` and captions as timed lines `GET /v1/ugc/transcript`, searchable by words — InnerTube `next` / ANDROID `player`), `video_search` takes `filter` (short / medium / long / today / week / month: YouTube's filter menu, Bilibili's duration and publish-time range) — all in `server/src/ugc.ts`; `catalog_list` / `catalog_item` only when 隐藏内容 is on (the app sends `adult`).
  - write (ordinary user actions, only when asked): `cast_to_tv` (a library movie or episode to a TV by DLNA) and `tv_control` (status / play / pause / stop / seek / forward / back / volume on that TV). Both run on the phone, which shares the TV's network: the server sends a `cast` / `tv` event with a request id, the app acts on the named / last-used / first-found TV and posts the outcome (for `tv`: state, position, duration, title, volume) to `POST /v1/ai/phone/:rid`, which the tool waits ≤ 45 s for (`server/src/ai/chat.ts` phone round trip, `app/src/lib/assistantCast.ts`), `ingest_resource` (by the short ref `find_resources` gave — the model never handles magnets), `auto_ingest` (batch: one `/v1/ingest/auto` job for ≤ 20 works), `subscribe`, `retry_task`, `refresh_library_item`, `manage_indexer` (add a public Prowlarr indexer by definition, enable / disable one; never delete).
  - `subtitles`: list an item's subtitles (embedded tracks — listed only, reading one would mean downloading the whole video — and files beside the strm / the 115 video); search online across sources (`server/src/subsearch.ts`: 迅雷 — keyless, direct files with language and duration; 射手网 assrt.net packs with `ASSRT_TOKEN`, `assrt.ts`; sub_share for anime via the plugin — ranked by episode / duration match and 简 / 双语), list a pack's files, read any file or online source as timed lines (GBK / UTF-16 decoded; search by words with the lines around each hit — find a scene by its dialogue, then `tv_control` seek); install beside the strm or on 115, ASS aligned to the audio. Routes `/v1/subs/search|files|read|file`, `/v1/emby/item/:id/subtitles[/install]`; plugin `/hub/subs/*`. The player's 在线字幕 uses the same routes.
  - `app_api`: everything else the app can do, through the server's own `/v1` API (`ai/knowledge/api.md` lists it; the model reads it with `read_knowledge topic=api`). GET reads freely; writes only when asked; delete / cancel / remove calls are refused without `confirmed: true` (the owner said yes in the chat) and Emby deletes are forced to a dry run until then. Not reachable: `/admin`, `/v1/ai`, Emby account, JavDB login, logs / events, config, binary routes; catalog / AV only with 隐藏内容. Answers over 12k characters are cut with a hint to narrow the query. A path the server doesn't have (Fastify's own 404) returns the API list's nearest lines instead of "Not Found", so the model corrects a guessed route.
  - memory: `memory_save`, `memory_search`, `memory_forget`; past conversations: `list_chats` (any of the query's words in titles and Q&A, snippets; the current chat listed and marked `current`; no match → the recent chats, as in OKX Helper) and `read_chat` (one chat's text, poster cards as their works in order). The last six chat titles are in every system prompt.
  - nothing deletes, cancels, stops services, changes other configuration or reads credentials; only the listed routes are reachable.
  - plus the harness's WebSearch and WebFetch unless web search is turned off.
- `prompt.ts` — system prompt (English, answers in Chinese). It tells the model to batch (lookup_titles, auto_ingest, parallel calls; 3–5 rounds per recommendation) and to treat titles as possibly mis-heard: questions sent from speech arrive marked `[语音输入…]` (app sends `voice: true`), and an odd or unknown title is tried as homophones against recent plays, the library and web search before asking. Answers show things as cards with one ```` ```cards ```` block: one `ref | note` per line. Every tool result that has a page or a link carries a `card` ref (`movie:` / `tv:<tmdbid>`, `person:<id>`, `emby:<id>`, `bili:` / `yt:<video>`, `bililive:` / `ytlive:<room>`, `up:` / `ytc:<creator>`, `task:<hash>`, `sub:<id>`, `cat:<provider>:<id>`), and the tool registers that card's data (`server/src/ai/cards.ts`: shape poster / avatar / wide / row, title, subtitle, image, in-app path or web link + app URL scheme, badge, 入库 target) from the raw route data in the chat's card store (`Chat.cards`, newest 400). While the block streams, the server sends each listed ref's card as a `card {ref, card}` event (a ref no tool registered is looked up once — works, people, Emby items, subscriptions — else `null`, not drawn) and stores them on the answer (`cards`). So the prompt has one fixed rule however many kinds exist; a new kind = a builder in `cards.ts` + `card` in its tool's output + nothing in the app unless it needs a new shape. The app (`components/ai/AiBlock.tsx` CardsBlock) draws consecutive cards of one shape as a row (posters with 入库 / 全部入库, round avatars, 16:9 videos; tasks and subscriptions as list lines). The older ```` ```media ```` / ```` ```video ```` JSON blocks still render in saved chats. In-app Markdown links: `[绝命毒师](/media/tv/1396)`, `/person/<id>`, `/task/<hash>`, `/emby/<id>`, `/subscription/<id>`, `/tasks`, `/settings`.

SSE events: `chat {chatId}`, `card {ref,card}`, `text_start`, `text {delta}`, `think_start`, `think {delta}`, `think_end {ms}`, `tool {id,name,label}`, `tool_input {id,input,label}`, `tool_done {id,ok,output}`, `memory {text,replaces}`, `done {text,latencyMs}`, `error {error}`, `idle`; `: ping` every 15 s.

## Memory

Two layers (after Letta/MemGPT core vs archival, mem0's update-not-duplicate, Claude's memory tool): `profile` (≤ 12 stable taste / rules, always in the prompt) and archival `fact` / `watching` / `event` / `plan` (searched). Each turn, the archival entries most relevant to the question (+ chat title) are recalled into `<recalled>`; scoring is character-bigram overlap (no tokenizer, fine for Chinese) + tag hits + recency + use, in memory. `memory_save` updates a near-duplicate of the same kind (similarity ≥ 0.72) or `replaces=id` instead of adding; writes are serialized. Cap 400 entries (least recalled archival ones drop first). The app's 偏好与记忆 pane is `/v1/ai/notes` over the same store (owner entries are `profile`). The old `notes.json` migrates to `profile` on first load.

Usage and cost: each round's `usage` (input, output, cache write / read, web searches) is added up per turn; `settings.ts` prices it from Anthropic's price list (USD per MTok; web search $0.01 each, web fetch free) — the Messages API returns tokens, not money (OKX Helper's Agent SDK computes cost itself). Stored on the answer (`usage`, `costUsd`), sent with `done`, summed per chat in `/v1/ai/chats`; the app shows `7s · 18.2k tokens · $0.012`. A model without a price (a custom endpoint's) shows tokens only.

The system prompt is stable (cached; changes only with 隐藏内容); the per-turn part (time, profile, recalled, recent chats, screen) goes with the question.

## Knowledge (progressive disclosure)

`server/src/ai/knowledge/<topic>.md` — generic, owner-readable notes on how the stack works (platform, ingest, subscriptions, emby, selection, app, troubleshooting, adult). The system prompt carries only the index (`knowledge.ts` TOPICS, one line each; `adult` only with 隐藏内容 on); `read_knowledge` loads a topic when a question needs it. Nothing deployment-specific goes in these files — live values come from `platform_status`. Update the topic when the behaviour it describes changes.

## App

`src/lib/ai.ts` (state + connection: expo/fetch streaming, 40 s stale watchdog, backoff reconnect, resume on foreground / network), `src/lib/voice.ts` (hold / tap to talk on iOS speech recognition), `src/components/ai/*` (orb, step cards, Markdown, media blocks, history and preference panes), `src/app/ai.tsx` (the sheet), `src/components/AiSettings.tsx` (Settings → AI 助手). The orb passes the page it was opened from (work / person / task / Emby item / adult item) as context.

## Tests

`cd server && npm test` (node:test, no network): card refs and builders, the card store, step labels without `undefined`, list_chats search. Agent SDK wiring was checked live (tool call through AI_PROXY, resume, abort then resume).
